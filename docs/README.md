# OctoAcme Project Management Docs

## Overview

The OctoAcme project management suite covers the full software delivery lifecycle, emphasizing iterative delivery, clear ownership, data-driven decisions, and effective communication among stakeholders. Processes are structured to support onboarding, reduce dependency risks, and accelerate collaboration.

This repository's docs folder contains the canonical process documents for how OctoAcme runs projects. Use this README as the entry point to find guides, templates, and role descriptions.

## Key Project Management Processes

- **Initiation:** Validate ideas, align on objectives, define timeline and success criteria.  
  Link: ./octoacme-project-initiation.md

- **Planning:** Break down work, clarify backlog items, estimate effort, and map out dependencies and release milestones.  
  Link: ./octoacme-project-planning.md

- **Execution & Tracking:** Use project boards, structured standups, demo cycles, test quality, and monitor progress via metrics.  
  Link: ./octoacme-execution-and-tracking.md

- **Risk Management & Communication:** Maintain a risk register, communicate status, and escalate issues appropriately.  
  Link: ./octoacme-risks-and-communication.md

- **Release & Deployment:** Standardize hotfix, minor, and major releases with strong pre-release and rollback practices.  
  Link: ./octoacme-release-and-deployment.md

- **Retrospective & Continuous Improvement:** Run focused retros, document action items, and foster a culture of evaluation and improvement.  
  Link: ./octoacme-retrospective-and-continuous-improvement.md

- **Roles & Personas:** Understand the core roles (PM, PdM, Developer, QA, Stakeholder) and their communication patterns.  
  Link: ./octoacme-roles-and-personas.md

## How to use these docs

- Start with the Project Initiation and Planning guides when proposing or scoping new work.
- During execution, follow the Execution & Tracking and Risk Management documents for day-to-day processes and escalation.
- Follow Release & Deployment for production rollouts and rollback plans.
- After each cycle, use Retrospective & Continuous Improvement to capture learnings and action items.
